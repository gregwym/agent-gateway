# 产品需求

## 定位与价值

Agent Gateway 是一个自托管的 MCP Proxy。它让多个 Agent 通过统一入口调用获准的服务工具，
上游凭据由网关保管，访问范围和审批规则集中管理。

| 使用需求 | 产品提供的价值 |
|---|---|
| 多个 Agent 接入多个服务 | 客户端只连接一个 MCP 入口，通过 connection 选择服务账号 |
| 不向每个 Agent 分发服务密钥 | Agent 使用独立网关 Token；上游凭据只交给对应连接器 |
| 限制 Agent 的操作范围 | 按 Agent、连接和工具授权，并可限制参数与资源 |
| 对指定操作进行人工确认 | Passkey 批准绑定具体账号、工具及参数，只能使用一次 |
| 服务工具数量较多 | 按需搜索已授权工具，减少初始工具清单占用的上下文 |
| 维护接入与排查故障 | 网页管理、直接错误原因、凭据撤销和不含业务正文的审计 |

适用于需要独立控制 Agent 工具权限、管理多个服务账号的自托管部署。
管理员负责连接和授权，审批人确认具体操作，Agent 使用已授予的工具。

## 职责边界

| 组件 | 职责 |
|---|---|
| Agent | 理解需求、选择工具、处理和聚合结果、推理、记忆与调度 |
| Gateway | 认证、凭据管理、工具发现、路由、参数校验、权限、审批和审计 |
| 上游 MCP / Connector | 提供服务操作；必要时将明确的服务 API 包装为 MCP 工具 |

网关搜索的是工具和连接元数据。不同账号可共用工具名，调用时选择 connection；
这不要求上游返回统一的业务数据结构。

网关可以校验 schema、注入固定参数、限制结果大小、脱敏密钥和归一化错误。
连接器可以做协议适配，例如 MIME 解析、日历格式转换和服务支持的批量调用。
跨来源的数据合并、订单状态推断、业务索引、LLM 调用和工作流编排由调用方或上游服务负责。

## 核心概念

| 概念 | 含义 |
|---|---|
| Agent / client | 通过独立凭据认证的调用方；Token 不证明当前聊天用户是谁 |
| Member | 可登记 Passkey 的人员身份，可作为账号所有者或审批人 |
| Member group | 成员、Agent 和共享账号的组织范围；当前配置字段名为 `household` |
| Connection | 绑定一个服务账号、上游地址或进程以及凭据的连接 |
| Owner | 连接所属的成员或组，不因所有权自动获得 Agent 工具权限 |
| Approver | 有权批准该连接调用的成员，或组内任意成员，与 owner 分开配置 |
| Tool binding | 已审阅的上游工具及其参数限制、内部别名和授权关系 |

新 Agent、新连接和新增能力默认无授权。组成员关系不产生权限继承。
共享 Token 的所有使用者共享同一套权限；需要不同权限时使用独立凭据或额外的可信身份机制。
当前产品不提供企业多租户的管理员隔离或复杂 RBAC。

## 功能要求

| 编号 | 要求 | 验收标准 |
|---|---|---|
| F01 连接管理 | 注册、编辑、验证和删除 MCP 上游；同一服务允许多个账号 | 连接独立配置；错误说明直接原因；无效配置不覆盖已生效状态 |
| F02 凭据管理 | 加密保存上游凭据，按连接注入，支持替换和删除 | Agent 无法读取上游凭据；日志、错误和工具结果不泄露已知密钥 |
| F03 认证与授权 | 每个 Agent 独立认证；按连接、工具授权，默认拒绝 | 未授权能力不可发现、不可调用；参数、Cookie 或请求元数据不能冒充身份 |
| F04 读写策略 | 禁止访问、只读、读写；读写各自选择无需审批或每次审批 | 内置邮件的发信与整理分别授权；未分类工具不自动视为读取 |
| F05 发现与路由 | 搜索工具、搜索连接、在选定连接执行 | 搜索支持分页并按当前权限过滤；每次执行重新检查权限和参数 |
| F06 参数限制 | 支持固定参数及允许值，限制可访问资源 | 固定参数不接受调用方覆盖；越界参数在调用上游前拒绝 |
| F07 人工审批 | Passkey 决定绑定一次调用，支持拒绝、过期、撤回和单次消费 | 换账号、工具或参数需重新批准；并发重放最多执行一次；审批人由配置决定 |
| F08 定义变更 | 审阅和锁定工具描述/schema；支持连接器升级 | 未审阅的远程变化停用相关工具；内置升级保留限制，新能力默认拒绝 |
| F09 网页管理 | Passkey 管理会话；成员、Agent、连接和权限管理 | MCP Token 不授予管理权限；放宽授权、修改审批人和签发凭据需要一次新的 Passkey 确认 |
| F10 审计 | 记录调用方、连接、工具、结果、耗时与审批状态，支持保留期限 | 不记录邮件正文、完整业务结果或参数值；错误可关联审计记录 |
| F11 生命周期 | 超时、并发限制、断线恢复、原子配置切换和撤销 | 失败不发布部分配置；保存结果不明时先查询状态；不自动重试结果不明的写入 |

审批绑定最终发送给上游的参数。批准在执行前消费；上游失败不会自动恢复批准。
批量操作必须报告每项的成功、失败、未执行或结果不明，不能把部分成功描述为全部完成。

## 当前能力

基线版本：`0.7.0`。以下状态描述实现范围，真实提供方兼容性需单独验证。

| 能力 | 状态与限制 |
|---|---|
| stdio / Streamable HTTP Proxy | 已实现；远程 HTTP 支持网页配置，stdio 由主机配置；支持独立凭据、工具锁、别名和策略 |
| 网页管理 | 内置连接器及通用远程 MCP、成员、Agent、Token、权限与连接检查已实现 |
| 工具发现 | 默认三个入口：`gateway_search_tools`、`gateway_search_connections`、`gateway_call_tool` |
| Passkey 审批 | 同进程实现可用；外部审批服务 adapter 尚未实现 |
| IMAP + SMTP | 同一连接提供邮件读写、分页、批量操作和发送；SMTP 暂不支持附件发送 |
| CalDAV | 只读日历、事件与冲突检查；列表有数量限制，无续页 |
| Gmail | OAuth 默认只读；可选发送和邮件整理，包括已读、星标、标签、移动、归档和废纸篓；无搜索续页、批量读取或永久删除 |
| Reminders | 实验性只读 EventKit helper；依赖 macOS 会话与系统授权，列表无续页 |
| OAuth | Gmail 及通用上游 MCP OAuth 已实现，包括发现、PKCE、刷新及撤销；网关客户端 OAuth 尚未实现 |

现有自动验收使用模拟账号、隔离的替身服务、虚拟 WebAuthn 认证器及容器。
测试通过仅代表覆盖到的功能，不证明所有平台、浏览器或实体认证器均兼容。

## 接入扩展

优先复用现成 MCP；只有服务提供明确 API、且缺少适合的 MCP 时，才增加薄适配器。
传输兼容不等于平台接入完成。每个集成需要记录认证方式、账号边界、允许的工具、接口版本和验证结果。

| 接入类别 | 能力范围 | 当前状态 |
|---|---|---|
| 邮件、日历、任务 | 服务原生查询与授权操作 | 已有部分内置连接器，见上表 |
| 电商与订单 | 代理提供订单、配送、退货等工具的 MCP 或正式 API | 待评估；读取通知邮件不计为电商平台集成 |
| 财务数据 | 代理外部财务系统的受控查询接口 | 待接入；银行连接、交易同步和对账由上游负责 |
| 设备与基础设施 | 状态、监控及明确的运维操作 | 待接入；使用受限服务接口 |
| 文件与媒体 | 搜索、读取及经授权的管理操作 | 待接入 |
| 通信与内容 | 代理实际账号获准访问的消息、订阅等能力 | 待接入 |
| 专业数据服务 | 单独设置账号与权限的业务接口 | 待评估，不默认纳入共享授权 |

不提供任意 URL、Shell 或 SSH 执行，不建设浏览器自动化代理。
缺少可靠接口的集成保留为待评估，不自动采用提取 Cookie 或长期保存浏览器会话的方案。

## 通用远程 MCP 的网页管理

### 交付范围

1. 网页新增和编辑命名的 Streamable HTTP connection，配置账号、owner、URL，以及 OAuth、Bearer、API Key 或无需认证。
2. 预览工具及 schema，审阅要注册的工具与读写分类；保存后通过现有权限入口显式授权。
3. 已授权工具通过现有搜索和执行入口使用，保留上游服务语义。
4. 检查 MCP 初始化与工具发现，明确区分连接成功和业务账号可用。通用连接检查不执行任何业务工具；业务账号能力由 Agent 在获准后验证。
5. 支持凭据更新、连接删除、定义变化处理、断线恢复及可定位的错误反馈。

6. OAuth 支持授权服务器发现、PKCE S256、已注册客户端、动态注册及客户端元数据 URL。授权绑定发起登录会话和配置版本。
7. OAuth Token 加密持久化，自动刷新并保存轮换后的刷新令牌；失效时提示重新授权。撤销先停止网关使用，再尝试服务商撤销，并区分两者结果。

自定义 stdio 命令由主机配置。通用 OAuth 与 Gmail 使用独立的协议验收；Gmail 校验 Google 授予的 scope 与所选权限完全一致。

### 验收

- 两个模拟上游使用同名工具和独立凭据，两个 Agent 按授权发现并调用正确连接。
- 网页新增、编辑、更新凭据、删除及重启恢复完整；失败不破坏现有连接、Token、权限和限制。
- 未授权调用、参数越界、工具定义漂移及无效审批在执行上游业务操作前拒绝。
- 认证、TLS、网络、协议和超时错误在 UI 上给出原因，敏感内容不回显。
- 密钥不出现在工具发现、调用结果、异常或审计中。
- OAuth 覆盖重复回调、跨会话、配置变化、issuer 不匹配、授权拒绝、并发刷新、重启及凭据撤销；刷新不改变权限版本。
- 代理到指定上游的调用不额外触发跨来源查询，不新增业务数据存储或 LLM 调用。

## 运行与安全要求

Gateway 应运行在 Agent 无权读取凭据、修改配置或控制进程的环境中。容器隔离不等于防御主机管理员。
stdio 上游与 Gateway 同用户运行，属于信任边界；需要更强隔离的上游使用独立运行环境。

只读应尽可能由上游凭据权限保证。上游不提供只读凭据时，应说明应用层限制与凭据实际权限的差异。
工具内容可能包含 prompt injection；网关保证调用仍受权限约束，不承诺内容可信或第三方模型零留存。

配置、凭据、密钥与审批状态应有明确的备份恢复步骤。日志不保存业务正文，部署示例使用占位值。
具体配置与限制见 [部署说明](deployment.md)，执行机制见 [设计说明](design.md)。
